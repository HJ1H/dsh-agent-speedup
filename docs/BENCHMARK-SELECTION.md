# 基准选型记录：为什么不用 SWE-bench / HumanEval 做宣传

日期：2026-11-03。记录这一轮实测的结论，避免以后重复踩坑。

## API 现状（sensenova 免费池）

| 模型 | 状态 | 说明 |
|---|---|---|
| `sensenova-6.8-flash` | **可用** | 1.2–2.4 s 响应，串行/4 并发均 200 |
| `sensenova-6.8-flash-lite` | 可用 | 更弱，复杂任务跑不完 |
| `deepseek-v4-flash` | 429 | 触发 TPM/RPM 限流 |
| `deepseek-v4.1-flash` | 403 | 当前套餐不含此模型 |

结论：只有 `sensenova-6.8-flash` 适合跑实验。

## SWE-bench 为什么不可用

试了 `psf/requests` 的两个实例，两种失败模式：

### 1. 内容安全过滤直接拦截

`psf__requests-6028`（代理认证 bug）的 prompt 含 `proxy`、`authenticate`、`auth` 等词：

```
dsh: INVALID_REQUEST: 400: {"message":"safety check failed","type":"failed_precondition_error","code":"9"}
```

两组都在第一次请求就被拦，**0 次有效工具调用**。这不是插件问题，是免费池的内容审核。

### 2. 免费模型跑不完长任务

`psf__requests-2931`（干净 prompt）能跑，但：

| 组 | 墙钟 | 工具调用 | 结果 |
|---|---|---|---|
| off | 240 s（超时） | 28 次 | exit=1，未完成 |
| on | 14 s | 3 次 | exit=0，模型提前收工 |

**这不是有效对比**——off 组在探索阶段就超时，on 组则因为模型没真正干活而"快速完成"。

off 组 28 次调用里确实有 5 次重复读（缓存的目标场景），但任务本身没跑完，无法据此得出结论。

## HumanEval / MBPP 为什么不可用

- HumanEval：164 题，每题"写一个纯函数"，全程 **0–2 次工具调用**，几乎无重复读。
- MBPP：同类形态。

我们的缓存/预取/并发在这些任务上**根本不触发**。用它们开关插件，两次输出会完全一致。

（HarnessMM 能用这两个基准，是因为它砍的是**模型推理调用**，机制不同。）

## 我们自己基准的可信度

| 基准 | 形态 | 样本 | 结果 | 用途 |
|---|---|---|---|---|
| T5（slow glob + 4 读） | 2 s 固定延迟工具 | 12 轮配对 | 工具耗时 −79.4%，24/24 pass | 缓存/预取 |
| T6（4 条只读 pwsh） | 真实 PowerShell | 12 轮配对 | 工具窗口 −66.3%，24/24 pass | 调度 |

两者都是 A/B 交替配对，配对差值 12/12 全负，95% CI 很窄。

## T8 实验（未采用）

设计了一个"代码审查"任务（glob + 读 4 个文件 + 读 package.json），想模拟真实探索流。结果：

- off 组：6 次调用，pass
- on 组：2 次调用，**fail**（只读了 package.json，跳过了那 4 个文件）

原因是模型看到 glob 返回的文件列表后，直接用文件名回答了"函数名"，没去读文件内容。这是**指令遵循能力弱**，不是预取导致的——T5 上 24/24 全 pass，两组调用数完全一致（各 5 次）。

T8 需要更强的模型才有意义，暂不采用。

## 结论

- **宣传视频**：用 T5 + T6 的稳定数据，不受模型波动影响。
- **论文/README**：可以引用 T5/T6 的配对统计（有 CI、有效应量、有原始数据）。
- **SWE-bench**：等有稳定付费模型且能跑完 240 s+ 长任务时再试；免费池上不可行。

## 补充：`deepseek-flash`（v4.1 推理模型池）实测

用户提供的 model_id `deepseek-flash` 可用，但配额极紧：

| 测试 | 结果 |
|---|---|
| 单次调用 | 间歇性 200，多数 429 `EndpointRPMExceeded` |
| 20 次尝试（间隔 4 s） | **成功 3/20 = 15%** |
| 响应结构 | 推理模型：`content` 为空，内容在 `reasoning_content`，`max_tokens` 全被推理消耗 |
| dsh 端到端（单个读文件任务） | 300 s 内未完成，超时退出 |

按 15% 成功率，一个需要几十次请求的 agent 任务无法完成。dsh 的 retryPolicy
（8 次重试 + 20–90 s 退避）理论成功率仅 `1-0.85^8 ≈ 73%`，仍然不够。

**结论**：该模型当前配额下不可用于任何基准实验。需要：
- 等待配额恢复，或
- 使用付费档，或
- 换用 `sensenova-6.8-flash`（本次实测唯一稳定的免费模型）。
